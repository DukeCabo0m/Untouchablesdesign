🔍 DIAGNOSTIC RAPIDE

Erreur dans la console :
→ [API] Error for /stats/dashboard: HTTP Error: 401
→ Stats error: Error: HTTP Error: 401

Cause :
→ Le token de session (UUID custom) n'est pas reconnu par Supabase
→ Supabase rejette les tokens non-JWT au niveau de l'Edge Function

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔧 SOLUTION (1 ligne de code)

Fichier : /src/app/utils/api.ts

AVANT :
```typescript
statsApi.getDashboard: () => apiFetch<any>('/stats/dashboard')
```

APRÈS :
```typescript
statsApi.getDashboard: () => apiFetch<any>('/stats/dashboard', {}, true)
                                                               ^^^^^^^^^ 
                                                               skipAuth = true
```

💡 LEÇON TECHNIQUE

Deux types d'authentification Supabase :

1. Niveau Supabase Edge Function (obligatoire)
   → Vérifie la présence du header Authorization
   → Accepte : publicAnonKey OU token JWT valide
   → Rejette : tokens custom (UUID, etc.)

2. Niveau Application Hono (optionnel)
   → Notre code peut faire ses propres vérifications
   → Vérifie le token de session dans le KV store
   → Gère les permissions utilisateur

Notre token UUID fonctionne au niveau 2, mais PAS au niveau 1.
Solution : Utiliser publicAnonKey pour bypasser le niveau 1.
